# 质量审查

发布或重审时，平台默认使用 **HaluCatch** 对 Skill 包做 **五维静态质量评估**。与 SkillSpector 互补：HaluCatch 关注 **可维护性、规则完整性、护栏与复杂度**，不替代安全扫描。

平台 **不会运行** Skill 包中的脚本；HaluCatch 只读取快照文件内容。

## 在详情页哪里看

Skill 详情 → **审查与评估** → **HaluCatch 质量评估**（当 provider 为 HaluCatch 时）：

- **五维雷达图**：与平台内其他 Skill 的平均水平对比（若有足够样本）。
- **Tasks x/y**：五维中通过维度数量（每维对应 HaluCatch 一个检查模块）。
- **报告摘要**：取自标准版报告的简短 Markdown。
- **查看完整报告**：进入独立页面，切换 **专业版 / 标准版 / 行动版** Markdown。

**行动版** 报告可下载为 `.md`，便于在 Cursor 等工具中 @ Skill 目录，按条目改进包。

## 五个维度

| 维度 | 关注点（简述） |
| --- | --- |
| **地基与数据管线** | 脚本与依赖是否固化、路径与输入是否可移植、基础工程习惯 |
| **代码风险** | 错误处理、硬编码、超时、常见危险写法（静态可见部分） |
| **规则与方法论** | 步骤是否清晰、边界与输出是否自洽、指令是否可执行 |
| **解读护栏** | 验证、失败回退、确认机制、输出是否过于开放 |
| **复杂度与可维护性** | 文档与脚本复杂度、引用链、指令密度是否过高 |

各维在雷达上的数值由 HaluCatch 对该维 issue 的 **pass / warn / fail** 等状态综合得出；详情页 **Tasks** 统计的是维度级通过情况，不是「五个测试用例」。

## 三份 Markdown 报告

| 版本 | 适合谁 |
| --- | --- |
| **专业版** | 完整技术细节与 issue 列表 |
| **标准版** | 平衡长度，详情页摘要通常来自此版 |
| **行动版** | 面向 AI 助手的可执行修改清单，支持下载 |

报告语言随 Skill 类型与 HaluCatch 配置，常见为中文或英文。

## 评估状态徽章

| 徽章 | 含义 |
| --- | --- |
| 可靠性通过 | 五维整体达到通过阈值 |
| 部分通过 | 存在需改进项但未整体失败 |
| 可靠性失败 | 存在较多 fail 或关键维不达标 |
| 未配置可靠性评估 | HaluCatch 未运行或回退到其他 provider |

当 HaluCatch 不可用时，平台可能使用 **`tests/*.json` 静态任务集** 做简化评估（provider 非 `halucatch-adapter`），详情页展示方式会不同。

## HaluCatch 不可用时的表现

`inspection` 记录中可能出现 HaluCatch 相关提示；运维需保证：

- Python 3.8+ 可用（Windows 常见为 `python`，Unix 常见为 `python3`）
- 仓库内 `packages/halucatch-1.8.8` 存在  
- 可选：`HALUCATCH_PYTHON`、`HALUCATCH_DIR`、`HALUCATCH_TIMEOUT_MS`  
- 设置 `HALUCATCH_ENABLED=false` 可强制禁用 HaluCatch  

用户侧：若长期看不到雷达与报告，请联系管理员；作者仍应保证 `SKILL.md` 与 `tests/` 质量。

## 与 SkillSpector 如何配合使用

| 维度 | SkillSpector | HaluCatch |
| --- | --- | --- |
| 目标 | 恶意与高风险行为、外泄、注入等 | 文档与结构质量、可维护性 |
| 详情入口 | 安全审查 | HaluCatch 质量评估 |
| 典型动作 | 删危险指令、减权限、去重复填充 | 补步骤、加护栏、降复杂度 |

建议 **两者都看过** 再决定是否在团队内推广某版本 Skill。

## 改进后如何更新结果

HaluCatch 结果绑定 **版本内容 hash**。修改包后必须 **发布新版本**，才会生成新的评估与报告；旧版本记录不会被覆盖。
